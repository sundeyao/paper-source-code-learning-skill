# 训练、推理、损失与后处理

## 分清阶段
```text
模型计算
├── 训练路径（若有）：目标准备/匹配 → loss → backward → optimizer
├── 推理路径（若有）：解码/评分 → 过滤或后处理 → 输出
└── 评估路径：预测与标注比较 → 指标汇总
```
这是概念分类，不是固定架构。依当前实现增删分支。

## 训练路径核验
- 模型输出和标注的格式是什么？
- 是否有 matcher/assigner？如何调用？
- loss 的各项输入、计算公式和权重是什么？
- 哪些层/分支的输出参与损失？
- 梯度怎样回传？哪些参数被冻结或进入 optimizer？
- 推理是否跳过这些训练专属步骤？

## 推理路径核验
- 预测如何解码？
- 是否有 threshold、Top-K、NMS、beam search、采样、重排、合并或其他后处理？
- 每个步骤使用什么分数、维度、阈值、数量或停止条件？
- 输出怎样映射回原始输入坐标、文本、ID 或其他数据？
- 后处理是在模型代码、服务层还是部署流水线？

不要假设任何具体机制存在。找到实现和调用点后再说明。

## 常见概念的区分
- **匹配/分配**：将预测与目标建立训练对应关系（若该方法使用）。
- **筛选/排序**：按分数或规则选择候选。
- **抑制/去重**：删除或降权重复候选。
- **合并**：将多个结果组合成一个结果，通常是独立逻辑。
- **裁剪/序列化**：转换或导出结果，不必然改变模型预测本身。

## 分类归一化注意事项
Sigmoid 与 Softmax 的语义不同，但应以当前分类头和 loss 为准。Sigmoid 通常独立映射每个类别；Softmax 在指定轴上归一化。不能仅凭分数高低断言预测语义正确。

## 反向传播
区分 loss 数值、对输出的梯度、计算图中的梯度传播和 optimizer 参数更新。只有参与计算图且被 optimizer 管理的参数才会按相应梯度更新。

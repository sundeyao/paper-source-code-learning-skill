# 训练、推理、匹配与后处理

## 先把阶段分开
```text
模型前向
   ↓
训练：匹配/分配 → 计算损失 → 反向传播 → 优化器更新
推理：分数与坐标 → 实际后处理 → 输出结果
```
这是分类框架；具体模型可能有辅助损失、多个 Decoder 层输出、集合预测或其他分支，必须检查实现。

## 训练阶段要查什么
- 模型输出和真实标注分别是什么格式？
- 使用哪种 Matcher / Assigner？在哪里调用？
- 匹配成本包含分类、L1、IoU 或其他项吗？
- 匹配结果怎样传给 Criterion / loss？
- 哪些预测参与损失：最终层、中间层、Encoder 输出或辅助头？
- 每项 loss 怎样合并，怎样参与反向传播？
- 推理时这些训练组件是否仍执行？

### 匈牙利匹配
若源码使用 Hungarian matching，追踪 cost matrix、真实目标与预测集合的维度、assignment 返回的索引，以及未匹配预测怎样参与分类/回归损失。不要把匹配误认为推理阶段的 NMS 或 Top-K。

## Top-K 核验清单
每次解释 Top-K 都明确：
1. 输入张量来源和形状；
2. 排序对象是空间位置、Query、类别，还是 Query-class pair；
3. 排序轴；
4. Top-K 前是否先 `max`、`sigmoid`、`softmax`、`flatten` 或其他转换；
5. K 的实际配置值和默认值；
6. 返回的分数和索引分别是什么；
7. 索引怎样映射回框、类别或特征；
8. 这一步是否仅筛选，是否还有独立去重逻辑。

不同阶段可能有多个 Top-K。用代码位置定义其语义，不要只凭“第一次/第二次”推断。

## NMS、阈值、框合并与裁剪
- **置信度阈值**：按分数门槛过滤，核对分数定义与阈值位置。
- **NMS**：依据分数与重叠度抑制部分候选；检查类别是否分组、IoU 阈值和实现调用。
- **框合并**：将多个框坐标合成为一个区域，是独立的几何/业务逻辑；不要把 NMS 当成合并。
- **图像裁剪**：按坐标从原图提取像素；通常不等于修改模型预测。
- **排序/阅读顺序**：可能单独预测或在后处理计算，不能自动视为框去重。

只有在当前执行路径找到实现或调用，才声称操作确实发生。

## Sigmoid 与 Softmax
若分类头使用 Sigmoid，各类别分数通常独立映射到 `[0,1]`，不强制总和为 1；多个类别分数可以同时偏高。若使用 Softmax，类别分数在归一化轴上相互竞争并总和为 1。训练损失会鼓励模型区分正负类别，但不等于数学上强制每个 Query 只能输出一个类别。

## 反向传播
区分 loss 数值、loss 对输出的梯度、梯度通过计算图回传、optimizer 更新参数。不要笼统声称“一个损失函数把所有网络都改了”；检查哪些参数参与计算图、是否冻结，以及是否进入 optimizer。

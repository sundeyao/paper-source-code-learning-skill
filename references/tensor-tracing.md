# 张量形状与具体运算追踪

## 核心原则
解释张量时回答：它在哪里生成、形状是什么、每个维度表示什么、经过什么运算、为什么改变、下一步在哪里使用。

## 数据流表
| 阶段 | 变量 | 输入形状 | 运算 | 输出形状 | 下一步 |
|---|---|---|---|---|---|
| 1 | `feature` | `[B,C,H,W]` | 当前源码中的实际操作 | 依代码填写 | 下游模块 |

不要在未查看源码时预填固定通道数、层数、尺度数或 Query 数量。

## 常见维度符号
只在当前实现确实采用对应含义时使用：
- `B`：batch size。
- `C`：channels 或 classes；结合上下文区分。
- `H, W`：空间高度与宽度。
- `S`：展平后的空间位置数或 token 数。
- `Q`：Query 数量。
- `L`：特征层级数量。
- `D`：隐藏维度或每个 token 的特征维度。

明确区分 `[B,C,H,W]`（常见 NCHW）与 `[B,S,C]`（具体布局依实现而定）。

## 必须讲清楚的操作

### Conv2D
检查 `in_channels`、`out_channels`、kernel、stride、padding、dilation。通道是否变化由 `out_channels` 决定；空间尺寸由卷积参数和输入尺寸共同决定。不要笼统地说卷积只改变通道。

### Linear / MLP
说明最后一个维度如何映射，例如 `[...,256] -> [...,C]`。Linear 通常保留前面的维度；MLP 的层数、激活和归一化以实际代码为准。

### Reshape / flatten / transpose
用具体数字说明维度重排，例如 `[1,4,2,3] -> [1,4,6] -> [1,6,4]`，并说明 reshape 与 transpose 的区别。它们本身通常不执行可学习的特征变换。

### Concat 与逐元素相加
- `concat`：沿指定轴拼接，输出该轴长度增加；其他维度通常必须兼容。
- elementwise add：对应元素相加，形状需兼容或满足广播规则；不会像 concat 一样增加通道数。

### Broadcast
展示具体形状如何对齐。例如 `[1,S,4]` 与 `[B,S,4]` 在支持广播的框架中可沿 batch 维广播；这不代表先物理复制 B 份。核对框架规则和实际代码。

### Gather / Top-K / index
说明对哪个张量执行、沿哪个维度选择、索引代表什么、输出形状，以及后续是否做除法/取模或映射到另一个张量。

### Attention / sampling
不要只说“Query 与特征交互”。用户需要技术细节时，追踪 Query 投影、Key/Value 来源、维度拆分、注意力分数、softmax、采样位置、加权求和和输出投影，并以当前实现为准。

## 数值例子
维度或索引不直观时，先构造很小的示例逐步演算，再映射回真实形状。明确说明示例数字只是演示数据，不是模型实测输出。

# 源码阅读与调用链追踪

## 目标
把论文概念映射到当前仓库的真实实现，确认运行路径，而不只是列举模块名称。

## 1. 确认环境与入口
记录可获得的仓库路径、分支/提交、框架及版本、配置文件、训练入口、推理入口、模型构建入口和关键依赖。若无法获得版本信息，明确说明。

## 2. 建立调用图
```text
入口 → 配置/构建 → 数据准备 → 核心模块 → 输出/损失 → 后处理或评估
```
这只是查找路线，不是所有项目都必须遵循的架构。根据当前源码删改。

## 3. 关键函数五项核验
| 核验项 | 问题 |
|---|---|
| 调用关系 | 谁调用它？它调用谁？ |
| 输入 | 实际传入哪些变量、参数与配置？ |
| 运算 | 可执行语句具体做了什么？ |
| 输出 | 返回哪些张量、结构或副作用？ |
| 下游 | 输出被谁消费？ |

## 4. 证据等级
- **源码已确认**：检查了实现和相关调用点。
- **论文说明**：论文明确描述，但代码尚未核实。
- **推断/待验证**：有依据的假设，仍需要更多代码或实验。

## 5. 避免错误
- 类存在不代表它在当前配置中启用。
- 注释和命名是线索，不是实现证据。
- 如果一个操作没在当前文件中出现，继续查调用链和相关模块后再判断。
- 只搜索了部分代码时，要明确范围。
- 不混用不同框架、fork、commit、训练和部署版本。
- 不编造行号；无法获得时给出文件路径与符号名。
